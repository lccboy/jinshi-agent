# 题材库历史归档 / 今日实时双态计划

## 目标

题材库默认展示收盘后归档的不可变日视图，并允许在详情栏选择历史交易日；用户主动打开“今日实时”后，以当日盘中快照覆盖涨停股、题材/概念涨停数、模型命中和事件流，关闭开关后恢复此前选择的历史日期。实时层不得写回或伪装成历史归档。

## 任务 1：实时聚合接口（TDD）

1. 先为 `/api/intraday/latest` 增加失败测试，覆盖盘中快照、涨停池、涨停原因、模型命中和事件的合并。
2. 接口以最新 `intraday/<date>/snapshots.ndjson` 的日期为准，读取同日 `facts`；即使行情快照为空，也保留事实池与事件。
3. 返回明确的 `data_date`、`ts`、`phase` 和 `available`，前端据此展示正常、空数据或降级状态。

## 任务 2：题材库双态 UI

1. 在题材详情右上方增加历史日期选择器、“今日实时”开关和刷新状态。
2. 历史模式继续读取 `day_<date>.json` 中收盘冻结的 `theme_limitup` 与 `theme_concept_limitup`。
3. 实时模式按当前涨停池重新计算题材与主/细概念计数，并显示当日模型命中；不改变历史缓存。
4. 集合竞价/连续交易阶段每 3 秒刷新，其余阶段每 30 秒刷新；切换页面或关闭开关时停止定时器。
5. 实时请求失败或无快照时显示明确状态，不回退成历史数值冒充实时数据。

## 任务 3：归档口径与验收

1. 在数据模型中明确题材涨停统计随 15:20 日视图冻结，盘中实时层只读且不写回。
2. 增加前端结构测试与接口测试，运行全量测试和单日 `archive_job --verify`。
3. 构建部署后用浏览器验证：历史日期切换、实时开关、模型命中展示、关闭后恢复历史日期、无实时数据空态。
