# V0.5 生产化实现计划

## 验收目标

在 V0.3 每日调度、质量门禁和本机部署基础上，实现可审计、可备份恢复、可回滚、无仓库明文密钥的生产运行闭环；所有服务只监听本机，由 nginx 统一暴露。

## 任务 1：安全与配置审计（TDD）

1. 新增仓库敏感信息扫描器及测试，覆盖常见 token/password/private key，并允许模板占位符。
2. 检查 API 绑定地址、nginx 暴露范围和前端产物，不允许凭据进入 `apps/web`、`dist`、`data/web`。
3. 运行时密钥仅从环境变量或 Windows 用户级环境读取，仓库只保留变量名。

## 任务 2：备份与恢复（TDD）

1. 新增 `production_ops.py backup`：按清单备份 normalized/facts/archive/kline/web/runs/config，生成 SHA-256 manifest，原子完成。
2. 新增 `verify-backup`：逐文件校验大小和摘要，坏包返回非零。
3. 新增 `restore --dry-run` 与显式目标目录恢复；禁止直接覆盖工作区，实际恢复前保留现状快照。
4. 新增保留策略，默认保留 14 个日备份。

## 任务 3：部署版本与回滚（TDD）

1. 部署前保存现网静态目录和 nginx 配置，生成 release manifest。
2. 新增 `rollback-local.ps1`，列出/选择明确备份并恢复，恢复后验证 Web/API。
3. Git tag 作为代码回滚通道，部署备份作为运行文件回滚通道。

## 任务 4：服务守护、日志轮转和健康检查

1. 用户态守护进程纳管每日调度，并持续写心跳；任务计划可用时仍作为首选。
2. API、调度和采集日志统一进入 `data/runs/logs`，按大小/日期轮转。
3. `status.ps1` 检查进程心跳、最近质量报告、备份新鲜度、Web/API 健康。

## 任务 5：生产验收

1. 全量测试通过；敏感信息扫描无 fail。
2. 创建真实备份并校验；恢复到隔离目录后逐文件校验。
3. 本机部署产生可回滚版本；执行一次回滚演练后重新部署当前版本。
4. 输出 `docs/acceptance/V0.5-acceptance.md`，记录证据与仍需连续运行观察的指标。
