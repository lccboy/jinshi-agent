# V0.3 稳定每日运行收口计划

## 验收目标

在 Windows 单机环境中，以一个稳定入口完成交易日前置、盘中采集、盘后同步/策略/归档；阶段幂等、失败可重试、状态可查询，并用统一质量报告阻止残缺数据发布。

## 任务 1：交易日与每日运行状态（TDD）

创建 `services/collector/daily_runner.py`、`tests/test_daily_runner.py`。

1. 写失败测试：周末跳过；显式交易日历优先；运行状态只追加 attempt；已成功阶段幂等跳过；失败阶段可重试。
2. 实现 `is_trading_day`、运行清单和阶段执行器。
3. CLI 支持 `--date`、`--phase premarket|intraday|postmarket|archive|all`、`--dry-run`、`--force`。

## 任务 2：统一质量门禁（TDD）

创建 `services/collector/quality_gate.py`、`tests/test_quality_gate.py`。

1. 写失败测试：主数据覆盖、新鲜度、必需 facts、日K新鲜度、Web 视图体积与日期一致性。
2. 输出 `data/runs/quality_<date>.json`，每项为 pass/warn/fail，包含实际值、阈值和说明。
3. archive 阶段只有质量门禁无 fail 才允许更新 `day_latest.json`；历史日文件仍可生成供诊断。

## 任务 3：阶段编排与恢复（TDD）

1. premarket：主数据/题材新鲜度审计，准备 universe。
2. intraday：按交易时段动态节奏采集，异常退避，meta 记录心跳与错误。
3. postmarket：同步 K 线、资金因子、membership、策略。
4. archive：归档只增数据、生成 Web 视图、运行质量门禁并发布 latest。
5. 每阶段子进程超时、输出和退出码写入运行清单；失败不覆盖既有成功产物。

## 任务 4：Windows 调度与运维入口

1. 创建 `deploy/install-tasks.ps1`，注册开盘前、盘中、盘后、归档任务。
2. 创建 `deploy/status.ps1`，展示任务、最近运行、数据新鲜度和 API 健康。
3. 文档化安装、卸载、补跑和故障恢复。

## 任务 5：端到端验收

1. 非交易日 dry-run。
2. 使用最近交易日数据完成 postmarket/archive 重放。
3. API/Web/事件/预警池/历史查询自动验收。
4. 连续 5 个交易日质量报告全部无 fail 后，V0.3 验收完成并进入 V0.5。
