# 会员授权持久化与升级免重激活修复计划

## 根因

8790 的持久授权文件仍有效，但会员中心只从浏览器 localStorage 恢复状态。浏览器存储丢失、换浏览器或 localhost/127.0.0.1 来源变化后，页面误报未激活；重新提交同一码时又使用新生成的浏览器设备指纹，云端按设备绑定规则拒绝。

## 实施

1. 先增加测试，固定“本地持久授权为真源、浏览器不保存激活码”的契约。
2. 本地校验请求未携带激活码时，从 8790 私有 runtime 缓存补齐激活码和原设备指纹。
3. 同一激活码重复激活时复用已绑定指纹，避免升级后的浏览器指纹变化触发误拒绝。
4. 会员中心在 8790 上从 `/api/system/status` 恢复授权显示及会员编号。
5. 浏览器只保留非敏感会员编号，不再把激活码作为本地授权真源。
6. 验证旧授权升级保留、云端重新校验、页面显示、全量测试和发布升级。

## 边界

- 不放宽云端设备绑定、到期时间或套餐权限校验。
- 不在公共接口返回激活码或设备指纹。
- 安装升级继续只替换程序目录，保留 `data/runtime/license.json` 和会员私有数据。
