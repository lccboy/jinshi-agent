# 交易日 15:30 题材库与板块强度全量归档计划

## 目标

每个交易日收盘后 15:30 自动执行一次全量归档：先冻结开盘啦板块排行、子板块、成分股和涨停原因，再生成题材库与板块强度 Web 日视图，通过质量门禁后发布为当天归档。

## 实施步骤

1. 先写调度测试：15:29 不归档、15:30 且盘后阶段成功才归档、成功后不重复、失败最多重试三次且重试间隔不少于五分钟。
2. 新增收盘采集入口测试：校验 KPL 全量摘要、主板块成分文件及涨停原因文件，并把涨停原因按 `stock_id` 写入当天 facts；已有事实文件不覆盖。
3. 修改每日总控：archive 阶段依次执行 KPL 全量收盘采集、带 `--kpl-output` 的 Web 归档、质量门禁发布，确保题材库和板块强度使用同一冻结日期。
4. 修改用户态守护进程和 Windows 计划任务，将归档时间统一为 15:30，并加入有界重试。
5. 更新运行文档，执行单元测试、dry-run、真实收盘补归档、部署并检查调度心跳与当日质量报告。

## 数据边界

- KPL 是板块和涨停原因主源；题材字典仍来自规范化主数据。
- `facts` 与 `archive` 只追加；重复触发由每日运行清单幂等拦截。
- 只有质量门禁无 fail 时才更新 `day_latest.json`，失败保留日志和源文件供下次重试。
